# 阿米娅 LoRA

用《明日方舟》的剧情对话，把 **Qwen3-1.7B** 微调成一个会说话像阿米娅的模型。

从 1,943 个剧情文件里抽出阿米娅的 7,142 条台词，清洗成 1,588 条真实对话，在 8 GB 显存的笔记本上训了三轮。

---

## 效果

| 输入 | Qwen3-1.7B 原版 | 微调后（v1, checkpoint-200） |
|---|---|---|
| 帮我写一个 Python 快速排序 | 输出一大段标准代码 | **我……我不会。** |
| 我今天好累，不想干活了 | 建议你休息、喝水、做拉伸 | **……没关系，我来帮你。** |
| 今天天气不错 | 是的，今天天气不错，适合出门 | **是的，很适合去郊外。** |

第二行是关键。原版是一个热心但公式化的助手；微调后它**拒绝了自己不会的事**，而且是用犹豫的语气拒绝的 —— 这说明风格确实迁移过去了，不是套模板。

## 下载模型

三版权重（各 31 MB）在 Releases 页面。三个都能直接挂到 Qwen3-1.7B 上跑：

```bash
python scripts/chat_amiya.py --adapter dist/amiya-v1-ckpt200
```

| 版本 | 特点 | 建议 |
|---|---|---|
| **amiya-v1-ckpt200** | 人设最稳，回答短（中位 15 字） | **推荐** |
| amiya-v2-ckpt150 | 回答长，但会陷入循环复读 | 不建议 |
| amiya-v3-ckpt75 | 回答长，人设较弱 | 不建议 |

三者用的是同一份底模、同样的 rank 8 / alpha 16（8,716,288 个可训练参数，占 0.5%），区别只在数据。

v1 选 checkpoint-200：同一句话问它写代码，它会说「我……我不会」；训到 600 步之后，同一句就变成了「我给你写一个吧」。

## 三条结论

**1. 这份数据能教「怎么说话」，教不了「知道什么」。**

台词数据里只有「这句话怎么说」，没有「凯尔希是谁」。所以问知识类问题，它只会碎碎念：

```
凯尔希医生是谁 → 凯尔希医生是......
赫默是谁       → ......是......是......是......
```

训练 200 步和 519 步，这个结果**一个字都没变**。知识不该塞进参数，应该走 RAG。

**2. 短句数据塑造人设，长句数据塑造话痨。**

为了治「回答太短」，我把连续的台词合并成段落。长度确实从 8 字涨到 30~50 字，但**「我……我不会」这种干脆也没了**，变成了「嗯，我来写一个快速排序的代码……」。

短和干脆是同一件事。改成话多，就同时改掉了人设。

**3. 模板化的数据是最毒的。**

我把人物档案转成问答（「赫默是谁」→「赫默，罗德岛，黎博利，医生/研究者。」）混进去，只占 12%。结果整个模型开始无限复读：

```
给我讲讲罗德岛 → 罗德岛，罗德岛，罗德岛，罗德岛......
```

原因不是比例，是**可预测性**：模板句 loss 天然低，每一步都在贡献最稳定的梯度，模型用它换最低的损失。低熵数据不管占多少都会压过其他数据。

## 数据是怎么来的

```
ASTR 剧情原文 (1943 个文件)
        │  01_download_story.ps1
        ▼
切出 387,007 条「说话人：台词」
        │  02_extract_amiya.py
        ▼
阿米娅的 7,142 条（4 种名字写法）
        │  03_classify_amiya.py  规则分类
        ▼
6,228 条，7 个类别
        │  04_build_corpus.py  取「非战斗/非遗定」
        ▼
4,592 条语料
        │  06_build_trainset.py  取「上一句是别人说的」
        ▼
1,588 条真实对话对  ← v1 训练集
```

**关键的一步**：原文里阿米娅的台词，上一句若不是她自己说的，那就是一个真实的对话回合。这样不需要生成、不需要人工标注，白捡 1,588 条问答对。

分类结果（正则词表，5 分钟跑完 6,228 条）：

| 类别 | 条数 | 占比 |
|---|---:|---:|
| 剧情陈述 | 3,394 | 54.5% |
| 剧情设定 | 1,052 | 16.9% |
| 对博士 | 598 | 9.6% |
| 日常语气 | 536 | 8.6% |
| 战斗指挥 | 326 | 5.2% |
| 情绪柔软 | 178 | 2.9% |
| 日常关心 | 144 | 2.3% |

## 三次实验

| 版本 | 数据 | 步数 | train / eval | 结果 |
|---|---|---:|---|---|
| **v1** | 1,588 条单句对话 | 1,131（3 epoch） | 2.9 / 3.16 | 人设强，但回答只有 5~10 字，后期复读 |
| **v2** | 2,186 合并长句 + **300 条档案问答** | 590 | 3.2 / 3.19 | **循环崩坏**，12 个 checkpoint 里 9 个在复读 |
| **v3** | 2,186 合并长句（去掉档案） | 519 | — | 循环推迟出现，但**人设没立住**，知识题全崩 |

v2 → v3 是一次干净的对照实验：**只去掉 300 条档案问答，其他全不变**。循环起点从第 100 步推迟到第 150 步 —— 这就是定罪证据。

## 一个失败的路子（也留在仓库里）

[`05_gen_questions.py`](scripts/05_gen_questions.py) 是用本地 1.7B 反推「用户会问什么」——先有回答，再让模型猜问题。

**失败了。** 三个典型坏样本：

```
答：你们一定要平安无事......
问：你一定要平安无事吗？          ← 只是把答案改成问句

问：序号. 你是否认为责任是被强加的？  ← 格式污染
答：但是我不在乎。                ← 完全对不上
```

1.7B 做不了这种语义反推，它只会在原句上打转。所以最后改用「上一句是别人说的」这个笨办法，反而拿到了 1,588 条真对话。

## 复现

```bash
# 1. 依赖
pip install torch transformers peft accelerate
pip install -e LLaMA-Factory

# 2. 下载底模（约 3.9 GB）
modelscope download --model Qwen/Qwen3-1.7B --local_dir models/Qwen3-1.7B

# 3. 下载剧情原文（打包版，27 MB）
#    见 https://github.com/jsf322432/arknights-lore 的 Releases
#    解压到 raw_all/

# 4. 数据流水线
python scripts/02_extract_amiya.py
python scripts/03_classify_amiya.py
python scripts/04_build_corpus.py
python scripts/06_build_trainset.py

# 5. 训练（8 GB 显存，约 24 分钟）
llamafactory-cli train configs/amiya_lora.yaml

# 6. 聊天
python scripts/chat_amiya.py --adapter saves/amiya_v1/checkpoint-200

# 7. 批量评测所有 checkpoint
python scripts/eval_checkpoints.py --ckpt-dir saves/amiya_v1
```

显存不够时调小 `cutoff_len`，或把 `lora_target: all` 改成 `q_proj,v_proj`。

## 已知局限

- **多轮能撑 5~6 轮。** 再长开始跑偏，因为训练数据全是单轮对话。
- **回答偏短。** v1 中位 15 字。想要长回答会牺牲人设（见 v3）。
- **没有剧情知识。** 问设定只能得到“我不知道”。
- **贪心解码会循环。** 用采样（temperature 0.7）可以缓解，但没根治。
